# オーナー視聴フィードバック（2026-09-04）と、そこから決めた品質の単位

2本の作品（1日目 321秒、2日目 318秒）とデモ動画をオーナーが視聴した最初の記録。
**モデルの選択と人の判断を照合した最初のデータ**でもある。地名・ファイル名は書かない。

## 指摘（原文の要旨）

| 対象 | 指摘 |
|---|---|
| 1日目 | 3分より前は単調なハイウェイばかりで面白くない。**音楽がひどい**。クリップ間のルート図とショートタイトルは良いアイディア。だが**タイトルがストーリーを表せていない** |
| 2日目 | （意図と別の日のクリップだったが、それ自体は問題ない）1.0〜2.0分は似た映像が多く単調。**1.5分付近の大きな右カーブが入っていない**。音楽は最悪。それ以降のクリップ選択はまあまあ良い。タイトルは1日目と同じく要改善 |
| デモ動画 | **映像がない**。最後の数秒だけ実映像。カード中心の構成は映像製品のデモとして不適 |

## 診断

1. **視覚的な単調さ**: 同点処理の「道の種類」は**ラベル**の多様性であって**見た目**の多様性ではない。
   ハイウェイの窓は同じ family なので、似た絵が並ぶ。順位付けも「良い順」であって「違う順」ではない。
2. **GPS が知っている瞬間が候補で優遇されていない**: 映像の窓の列挙に切り替えたとき、
   GPS イベント（急カーブ・登り・停止）は**候補の理由**から外れた。大きな右カーブは GPS には
   見えているのに、12秒×30秒刻みの窓と選別が拾わなかった。
3. **章タイトルが汎用**（「道はつづく」の繰り返し）。GPS の事実（方向転換・登り下り・速度・
   経過距離・時刻）と、隣接する判定済み窓の記述を使えば、証拠に基づく題を付けられる。
4. **音楽**: 5曲の CC BY ライブラリがオーナーの好みに合わない。既定で付けるのが間違い。
5. **デモ**: 台本がカード中心。映像製品は映像で見せる。

## 品質の単位（Gate 7 に追加。**7.2 以降の費用削減より先**——安くて退屈な作品は売れない）

| 単位 | 内容 | 閉じ方 |
|---|---|---|
| **Q1 GPS の瞬間を候補に戻す** | GPS イベント（急カーブ・登り・下り・停止・出発・到着）の時刻を中心に窓を切り、列挙に**優先候補**として加える。順位付けの帯に必ず入れ、同点なら優先 | 2日目の「大きな右カーブ」が採用されること |
| **Q2 見た目の多様性** | 隣り合う採用窓の**視覚的類似**（1fps proxy のフレーム差・色ヒストグラム、無料）を測り、似すぎる窓を1本に。順位付けプロンプトに「互いに違う窓を選べ」を加える | 1日目の前半3分に同種の絵が3本以上続かないこと。オーナー再視聴 |
| **Q3 証拠に基づく章タイトル** | GPS の事実＋隣接窓の記述から題を生成（Gemini テキスト、数円）。「登りが続く／峠を越える／海沿いへ／町を抜ける」等。地名は GPX に無いので使わない | オーナーが「ストーリーを表している」と言えること |
| **Q4 音楽** | 既定を**無音**に。console で「なし／ライブラリ／自分の曲（private-media/music に置く）」を選べる。ライブラリは入れ替え候補を提示（CC BY / CC0 のみ） | オーナーが1曲は使えると言うこと |
| **Q5 デモを映像中心に** | 台本を「映像 70%・カード 30%」へ。カードは短く、映像の上にテロップ（HTML→PNG の透過重ね）。 | オーナーが「映像がある」と言うこと |

Q1〜Q3 は選別の核心なので、閉じたら**両 ride を再レンダーしてオーナーが再視聴**する。
